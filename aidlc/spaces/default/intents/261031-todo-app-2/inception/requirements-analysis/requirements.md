## Intent Analysis

学習者が Web クライアント開発の基本を練習できる、単一利用者向けの TODO アプリを提供する。初回リリースでは、TODO の追加、一覧表示、完了状態の切り替えと表示切り替え、ブラウザ内での永続化に集中する。

## Functional Requirements

### TODO の追加と表示

- FR1: システムは、利用者が空白のみではない TODO テキストを入力して追加できるようにしなければならない。
  - Given TODO 一覧が表示されている
  - When 利用者が有効なテキストを入力して追加する
  - Then 新しい未完了 TODO が一覧に表示され、ブラウザのローカルストレージへ保存される。
  - Given TODO 入力欄が空白のみである
  - When 利用者が追加しようとする
  - Then TODO は作成されず、入力欄に修正方法が分かるメッセージが表示される。
- FR2: システムは、保存されている TODO をページ読み込み時に復元し、未完了 TODO の一覧として表示しなければならない。
  - Given ローカルストレージに TODO が保存されている
  - When 利用者がアプリを開く、またはページを再読み込みする
  - Then 保存済みの未完了 TODO が保存順で表示される。
  - Given 保存済み TODO がない
  - When 利用者がアプリを開く
  - Then 空の状態と、最初の TODO を追加するための案内が表示される。

### 完了状態と表示

- FR3: システムは、利用者が各 TODO の完了・未完了を切り替えられるようにしなければならない。
  - Given 未完了 TODO が表示されている
  - When 利用者が完了へ切り替える
  - Then TODO は完了として保存され、既定の未完了一覧から非表示になる。
  - Given 完了 TODO が表示されている
  - When 利用者が未完了へ切り替える
  - Then TODO は未完了として保存され、未完了一覧に表示される。
- FR4: システムは、利用者が完了済み TODO の表示・非表示を切り替えられるようにしなければならない。
  - Given 完了済み TODO が存在する
  - When 利用者が完了済み TODO の表示を選ぶ
  - Then 完了済み TODO が未完了 TODO と区別できる状態で表示される。
  - Given 完了済み TODO の表示が有効である
  - When 利用者が非表示を選ぶ
  - Then 完了済み TODO は表示されない。

### 永続化と失敗時の扱い

- FR5: システムは、TODO の追加および完了状態の変更をローカルストレージへ保存しなければならない。
  - Given 利用者が TODO を追加または完了状態を変更する
  - When 保存が成功する
  - Then 次回のページ読み込み時に同じ TODO と状態が復元される。
- FR6: システムは、ローカルストレージの読み取りまたは書き込みに失敗した場合、失敗内容と次に取れる行動を明確に表示しなければならない。
  - Given ページ読み込み時にローカルストレージの読み取りに失敗する
  - When アプリが初期化を完了する
  - Then 保存済み TODO を表示せず、保存機能を利用できない理由を表示し、TODO の追加および完了状態の変更を無効にする。
  - Given 保存に失敗する
  - When 利用者が TODO を追加または状態を変更する
  - Then 画面上の変更と入力内容を保持し、保存失敗と再試行またはページ再読み込みの選択肢を表示する。

## Non-Functional Requirements

- NFR1: 一般的な開発用端末で、TODO の追加および完了・未完了の切り替えは利用者の操作から1秒以内に画面へ反映されなければならない。
- NFR2: システムは、幅375px、768px、1280pxのビューポートで、最新安定版 Chrome、Safari、Firefox において TODO の追加、一覧表示、完了・未完了の切り替え、完了済み表示の切り替えを利用可能にしなければならない。
- NFR3: システムは、初回リリースで WCAG 2.2 AA に適合しなければならない。主要な TODO 操作はキーボードのみで実行可能とし、入力・ボタンにはプログラム上の名前を付け、完了状態と保存失敗を支援技術へ通知しなければならない。
- NFR4: 実装後にテストを書き、CI で行カバレッジ80%以上を検証しなければならない。
- NFR5: 採用言語の標準的なフォーマッターと静的チェックを CI で実行し、違反した変更を統合してはならない。

## Constraints

- 単一利用者がブラウザ内でローカルに利用し、ログイン、サーバー API、データベースは使用しない。
- TODO データの永続化にはブラウザのローカルストレージを使用する。
- ステージングは `main` への統合後に自動配備し、本番配備には手動承認を必要とする。

## Assumptions

- A1: 対象ブラウザはローカルストレージを利用できる現行のデスクトップ・モバイルブラウザとする。具体的な対応ブラウザは後続設計で決定する。
- A2: TODO テキストの最大長、並び替え方法、完了済み TODO の保持期間は未指定であり、初回リリースでは実装時に合理的な制限を定める。

## Out of Scope

- TODO の編集、削除、期限、優先度、分類、検索、共有、複数利用者、認証
- サーバー側 API、データベース、クラウド同期、ファイルのエクスポート・インポート
- 完了済み TODO の自動削除

## Open Questions

- 採用するフロントエンド言語・フレームワーク、CI 実装、具体的な対応ブラウザ、アクセシビリティの適合水準は後続ステージで決定する。
