# アクセシビリティ確認リスト

## 参照した入力

- `../requirements-analysis/requirements.md` — NFR3 の WCAG 2.2 AA と主要操作
- `../user-stories/stories.md` — キーボード・支援技術での追加、完了、保存失敗
- `interaction-spec.md` — 部品ごとのキーボード、通知、フォーカス仕様

## 実装前の設計確認

- [ ] TODO 入力欄に可視ラベル「TODO を入力」がある。
- [ ] 追加、完了・未完了切り替え、完了済み表示、再試行、再読み込みはネイティブ操作部品または同等のキーボード操作を提供する。
- [ ] Tab で操作順に到達でき、Enter または Space で該当操作を実行できる。
- [ ] 入力エラーは入力欄直下に表示し、`aria-describedby` で関連付ける。
- [ ] 完了状態の変更は、TODO 名と新しい状態を支援技術へ通知する。
- [ ] 保存失敗は、理由と利用可能な回復操作をライブリージョンで通知する。
- [ ] 読み取り失敗時は、追加と完了切り替えが無効であることを支援技術にも伝える。
- [ ] 追加成功後は入力欄へフォーカスを戻す。
- [ ] 完了切り替え後は、操作したチェックボックスのフォーカスを維持する。
- [ ] 完了済み表示ボタンは状態に応じた文言と `aria-expanded` を持つ。

## 視覚設計の確認

- [ ] 通常テキストと背景は4.5:1以上のコントラストを満たす。
- [ ] ボタン、チェックボックス、フォーカスリングは隣接色と3:1以上のコントラストを満たす。
- [ ] 完了状態はチェック、取り消し線、状態テキストで示し、色だけに依存しない。
- [ ] エラーは色だけに依存せず、具体的な説明文と回復手段を示す。
- [ ] 375px幅で横スクロールを発生させず、操作部品を十分な大きさに保つ。

## 検証時の確認

- [ ] 幅375px、768px、1280pxで、追加、完了切り替え、完了済み表示・非表示をキーボードだけで実行できる。
- [ ] 最新安定版 Chrome、Safari、Firefox で、同じ主要操作と状態通知を確認する。
- [ ] 空の入力、保存済み TODO がない状態、読み取り失敗、書き込み失敗を確認する。
- [ ] 支援技術で、入力エラー、完了状態変更、保存失敗の内容と次の操作を取得できる。
